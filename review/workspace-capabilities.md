# 首版能力范围

首版目标覆盖思源内建对外 MCP 的全部工作空间读写能力，包括笔记本、文档、内容块、数据库、附件、文件、导入导出、历史、数据仓库和同步。用户在思源授权一个工作空间，连接其他空间需要再次授权。工作空间中现有的 MCP 工具暴露配置继续决定该连接能调用哪些工具。

## 工具清单与运行时

[工具源码快照](workspace-tools.json) 固定在 SiYuan `d08ac46c240d857417bc5fdba31167ad8afc3986`。其中 31 个内置工具具备对外投影资格，共登记 177 个操作，100 个操作在源码中声明了本地写入。计数来自静态工具声明，部分能力的效果和可用性随配置变化，最终清单需与运行中的思源核对。

- 用工作空间管理员权限在隔离的思源实例取得 `POST /api/ai/lsCapabilities` 的能力 ID、配置可用性和操作效果，再与同版本 `/mcp` 的 `tools/list` 核对对外工具及参数模式。记录准确版本和能力差异，用于生成随插件版本固定的待审核清单。
- 每个可调用操作拥有独立的工具名称、说明和参数模式。合并型工具的 `action` 由适配器固定，例如文档的创建、重命名、移动、复制和删除各自对应独立工具。复用内核现有实现继续保障权限、事务、兼容性和加密笔记本锁定。完整覆盖的验收是对外工作空间能力与适配器逐项核对，并记录每项最终审核状态。 [工具独立性和注解要求](https://developers.openai.com/plugins/plugin-guidelines#6-tools)
- 内置工作空间工具之外，另有仅供思源内置助手使用的能力，以及由插件注册、或调用其他服务的能力。思源目前会过滤仅供助手使用和导入自其他 MCP 服务的工具。动态注册能力也需要单独确认暴露配置、可分发的实现和审核清单。
- 导出、同步、网络请求和插件管理需要核对各自的工作空间边界、数据接收方和副作用。对查询范围、目标可配置性或影响动态变化的操作，按实际语义确定审核注解。覆盖修改、覆盖文件、删除和其他破坏性操作时，保留平台对不可逆操作的用户确认。
- 授权撤销、工作空间切换、工具暴露配置更新和只读状态变化应在执行前生效。发布验证用实际思源实例覆盖读取、新建、修改、删除、导入和同步等操作，并使用不同工作空间验证隔离。

## 当前验证包

现有 ZIP 只含搜索和读取，自动检查使用合成服务。它验证的是本地连接和工作空间边界可被桥接保留。完整工具适配与正式思源端授权仍待实现。正式送审时，隐私说明还需披露用户写入的内容、外发能力涉及的接收方，以及可能产生状态变化的操作。

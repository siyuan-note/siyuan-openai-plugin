# 本机 MCP 桥接与测试

当前验证桥接提供 `search_notes` 和 `read_note`。搜索默认返回最多 8 条、上限 12 条，每条包含标题、文档 ID、摘录和思源链接。读取返回最多 12,000 个 UTF-16 代码单元及截断状态。工具参数只允许关键词、数量或文档 ID。

桥接以 MCP stdio 方式运行。构建包包含 `plugin.json`、`mcp.json`、图标、本地进程和许可证。测试使用独立临时目录、临时证书和随机凭证，合成数据位于 `review/fixtures.json`。

## 验证接口

以下接口定义用于当前验证桥接。首版的完整工具适配以思源对外 MCP 为基础。

- 思源管理员确认配对，授权绑定到确认时的工作空间及实例。凭证由思源签发，思源端保存其摘要。
- 思源原子写入当前系统用户私有目录 `~/.siyuan-desktop-plugin/connection.json`，记录格式为 `{port, token, certificate}`。token 是 `sy_desktop_` 加 32 字节随机数的无填充 Base64URL。certificate 是本次授权使用的单张 PEM 证书，包含 `127.0.0.1` IP SAN，私钥留在思源。Unix 配置目录与文件分别限制为 0700 和 0600，Windows 由思源安装与运行流程验证目录和文件 ACL。
- HTTPS 监听器仅绑定 `127.0.0.1`。桥接固定连接主机和路由，从连接文件加载证书。重启、切换工作空间和证书轮换时，思源需同步维护连接文件与授权状态。用户必须单独授权目标工作空间。
- 服务校验 `Authorization: Bearer ...`，在执行请求前检查凭证是否撤销，以及它是否绑定到处理请求的工作空间和实例。搜索和按文档 ID 读取仅查询已授权工作空间。加密笔记本继续遵循现有操作租约与锁定规则。正文读取使用存储的文档内容，保持其中的附件与引用为链接。
- 搜索使用字面关键词。成功响应为 `{code: 0, msg: "", data: ...}`。过期、失效或撤销返回 HTTP 401。无权读取和不存在返回同一 HTTP 404。桥接拒绝重定向、无效证书以及超限或格式不符的响应。

| 路由 | POST 请求 | 成功的 data |
| --- | --- | --- |
| `/api/desktopNotes/search` | `{query, limit}` | `{matches: [{note_id, title, excerpt}]}` |
| `/api/desktopNotes/read` | `{note_id}` | `{note_id, title, excerpt, truncated}` |

思源现有通用 MCP OAuth 的授权状态保存在工作空间配置目录，授权后的调用具备 MCP 管理员身份。正式接入复用这套工作空间边界和工具暴露配置，保留各操作的鉴权、写入保护和加密笔记本锁定。

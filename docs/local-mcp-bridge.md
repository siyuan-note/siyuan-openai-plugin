# 本机 MCP 桥接与测试

插件在本机以 MCP stdio 方式运行。它用 Streamable HTTP 访问思源现有的 `/mcp`，按思源返回的工具清单提供具名操作，将参数和结果交给内核。包含 `action` 枚举的工具提供 `工具__操作` 形式的独立名称，例如 `document__create` 和 `block__get_kramdown`。参数中的操作由该名称固定。每次调用重新检查工具是否在当前工作空间开放，由思源校验参数、权限和副作用。

## 工作空间授权

- 插件只连接指定的 `https://127.0.0.1:<内核端口>`，使用所选工作空间的 `conf/ca.crt` 验证 HTTPS。此文件是 CA 公共证书。思源能为回环地址生成证书，普通本机服务无需启用局域网访问。
- 思源 MCP OAuth 启用要求工作空间需要登录。其公开地址字段填本机 HTTPS 源。工作空间已有其他 OAuth 来源时，切换公开地址会撤销该空间已有的 MCP 授权，应在思源中确认该变更。
- 授权通过浏览器使用思源既有的同意页面。插件验证回调状态和签发方、使用 PKCE S256，通过预注册客户端换取 `mcp offline_access` 授权。回调监听器只绑定 `127.0.0.1`。端口 49183 被占用时，可以在思源注册另一回调端口，并在连接命令中加 `--callback-port <端口>`。
- 使用浏览器打开授权页时，先通过工作空间内的 `conf/ca.crt` 确认这是本机实例的证书。插件进程仅信任这张 CA，不使用系统证书或关闭 TLS 验证。
- 连接保存在当前系统用户目录 `~/.siyuan-desktop-plugin/connection.json`。可以用绝对路径环境变量 `SIYUAN_OPENAI_CONFIG_DIR` 为独立客户端指定另一个私有目录。Unix 上连接文件是用户私有的 0600 权限。Windows 上选用由当前用户控制的目录及其访问权限。客户端密钥由终端隐藏输入。
- 访问令牌和刷新期限由思源控制。刷新在连接目录内串行化，轮换结果以原子写入保存。插件断开会调用思源的撤销端点。若工作空间已关闭，可以在下次打开时从思源 OAuth 设置中撤销客户端。
- 当前 stdio 进程在首次成功连接时绑定工作空间的源、证书和 OAuth 客户端。另一工作空间需单独授权并建立新的本地会话。

## 真实实例验证

先运行 `npm run build`。设置 `SIYUAN_TEST_KERNEL` 为待验证的思源内核可执行文件，`SIYUAN_TEST_APP` 为包含 `appearance` 等资源的应用目录。可选的 `SIYUAN_TEST_ROOT` 为已存在的独立测试目录。

```sh
node --test test/real-siyuan.test.mjs
```

测试用独立配置、临时工作空间、动态回环端口和随机密码启动两个真实内核进程，走完思源 OAuth 登录、同意、回调、令牌刷新和撤销。它还核对插件和内核的工具清单，对合成笔记执行新建、追加、编辑、读取和删除，并检查暴露配置与工作空间隔离。测试完成后关闭由测试启动的进程并移除临时数据。
